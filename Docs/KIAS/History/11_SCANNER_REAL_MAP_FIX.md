## Exterior advanced scanner contract
Second screenshot: advanced scanner is on a hull edge and looks **outward into space**; cyan outline indicates an **irregular, finite outside surveillance footprint that follows the projecting boundary of the ship on one side**. The image is a product reference, not precise measured polygon in tile coordinates. Introduce explicit `Exterior`/`OpenSector` mode only when outward orientation and hull-exterior seed are validated. Do not reuse `OpenToSpace` bounded circle; do not flood-fill infinite void or entire exterior of ship. Prefer shape generated from **ship hull geometry + facing + distance budget + obstacles/occlusion**; exterior cells may lie off-grid in map coordinates, so room's grid tile index alone cannot represent them. Pick a defensible deterministic algorithm: derive outer hull/occluder silhouette, determine outward half-plane, use tile/grid coordinates and transform to bounded range, restrict by sight/line-of-sight or shadowing of hull geometry, clip to available map/space. Ensure a cutout/stepped ship outline is reflected in shape and near-hull perimeter coverage, no detection through own hull. Exact user cyan shape need not be pixel-identical; explicitly produce visual overlay for acceptance. Exclude different grids only if intended by modules: exterior threat/spectral detector SHOULD detect eligible approaching exterior entities outside hull on map, not only transform.GridUid==source grid. Ownership/automatic control permissions MUST NOT cross grids.

Clarify scanner modes: InteriorRoom = true closed room; ExteriorSector = outward scanner; UnsealedInterior/OpenToSpace = destroyed/depressurized interior or open deck, NOT automatically same as ExteriorSector. Define mode selection using valid seed, facing, real geometry and exterior facing. Invalid ambiguous seed yields status and no permissive circular fallback. `Range` legacy may be used as **exterior** reach and UI shows labeled distance, but InteriorRoom is always full room. Advanced/basic capability differences remain module-based; do not give exterior threat sensors to a module lacking them.

### Door and wall invariants
Open/closed door remains semantic border, threshold belongs to adjacent rooms; open-door atmos flow must not merge rooms. On wall deletion, affected geometry invalidated quickly; on repair/door removal recalculate exactly; temporary bad geometry never emits phantom positives; transforms and rotations moving scanner invalidate scanner association. Limit exposure across hull openings by clear rules (breach is still interior unless explicitly reclassified) and tests. Reconciliation of `KiasCrewSystem`, `KiasIntegrationSystem.Reconcile/CanControl`, display + service-tool overlay, scanner module reporting all consume one geometry/index. Interior device control must not become global merely because exterior visibility is broad.
